## 1. Главное

1. Инструмент уже сильнее типичного решения на Colab: перебор, девять проверок
   «факт → порог → PASS/FAIL», стресс-матрица, загрузка данных, экспорт
   `results/`. Уникальность стоит искать не в новых экранах, а в том, чего нет
   ни в каноническом расчёте, ни в шаблоне организаторов: второй стресс (по
   спросу), честная проверка устойчивости выбора и прослеживаемость каждой
   цифры от файла организаторов до записки.
2. Уязвимость, которую надо закрыть первой. По собственной модели команды
   выбранный портфель FIRE-A · AGRI-B · TRANS-B · ENV-A стоит третьим (0,725),
   лидер — FIRE-A · AGRI-C · TRANS-C · ENV-A (0,737). При случайных весах лидер
   выигрывает в 48 % случаев, выбранный — в 8 %. Вопрос «почему вы взяли не
   первый по своей же модели» на защите неизбежен.
3. Ответ есть в данных кейса, и подгонять веса не нужно. Если коммерческая
   выручка не придёт вовсе, лидер модели не проходит порог `kcash ≥ 0,6`
   (якорные платежи покрывают 0,536 OPEX), а выбранный проходит (0,607). Из 143
   допустимых в STRESS такой тест выдерживают 18, и среди них выбранный —
   первый по баллу. Это и есть «второй стресс» команды: он объясняет гейт,
   усиливает П3/П4/П6 и делается за два часа.
4. Запас выбранного портфеля по c0 в STRESS — 40 млн руб. (3,5 %). Удорожание
   на 4 % ломает стресс; сменой режимов те же лоты выдерживают до 5 %, дальше
   только замена лота. Это готовый «реестр рисков, прогнанный через модель» (П7).
5. Порядок работ по цене балла за час: (1) стресс спроса S2, (2) блок
   «устойчивость выбора», (3) конструктор «что если» для демо, (4) проверка
   «цифры записки = цифры инструмента», (5) хэш-тест исходных файлов. Остальное
   по остатку времени или только текстом.

### Приоритет 1. До заморозки (17:00)

#### 4.1. Второй стресс команды: S2 «спрос»

**Что.** Помимо стресса организаторов (c0 ≤ 1180) — собственный стресс по
спросу: S2 «коммерческая выручка = 0» с проверкой `якорные платежи / OPEX ≥ 0,6`,
плюс мягкие варианты «якорь −20 %», «коммерция −50 %». Помечается как
допущение команды, не как канон.

**Зачем.** Объясняет гейт без подгонки весов: лидер модели S2 не проходит,
выбранный проходит и первый среди 18 прошедших; при случайных весах он первый
среди них в 58 % случаев против 8 % без S2. README организаторов сам
перечисляет «вероятностную модель спроса» среди того, чего канон не считает, а
заметка в `portfolio.json` уже признаёт, что коммерческий спрос требует
подтверждения. Реалистичность: коммерческая подписка на данные ДЗЗ на частном
рынке России появилась только в марте 2026 года (Спутникс), а доступ органов
власти к данным с 2025 года платный через федеральный фонд, то есть
«коммерция = 0, якорь = госконтракт» и есть нижняя граница рынка. Критерии:
П3 (кто платит в худшем случае), П4 (почему этот вариант), П6 (устойчивость),
Т3/Т4.

**Как у нас.** `backend/model.py`: функция `demand_stress(rec, lots, modes, cfg)`
→ покрытие OPEX якорем (формула готова в `tools/case02_robustness.py`);
в `model.json` блок `"team_stress": {"commercial_share": 0.0, "anchor_share": 1.0,
"kcash_min": 0.6}`; в `suggest` фильтр по S2 (или сортировка «сначала прошедшие
S2»); в контракт `combinations[*].checks.S2` как десятая проверка с пометкой
`"team": true`; в `payload.export_results` блок `team_stress` в `stress.json`.
Интерфейс: пятая плитка «Покрытие OPEX якорем 0,61 ≥ 0,60» и столбец в
стресс-матрице; в «Предложенных» серым те, кто S2 не проходит (как сейчас серым
для STRESS). Тест: лидер модели FAIL по S2, выбранный PASS, граница 0,6
включительно.

**Время.** A: 1,5–2 ч. B: абзац в разделе 3 («модель + два стресса»);
C: разделы 4 и 6 («якорь покрывает порог сам»); D: якорный платёж =
госконтракт или межрегиональное соглашение, коммерческий = опцион.

#### 4.2. Блок «Устойчивость выбора»: rank acceptability и интервалы весов

**Что.** Вместо заготовки «±20 % по весу» из шаблона — три честные цифры на
комбинацию: доля случайных векторов весов, при которых она первая; медианное
место; интервал каждого веса, в котором выбранная остаётся в топ-3. Плюс одна
фраза-вывод: «Рекомендация устойчива к …, меняется при …».

**Зачем.** README организаторов (§8.6, §15) прямо требует показать, меняется
ли лидер, и предупреждает, что заготовка ±20 % анализом не является. Rank
acceptability — стандартный приём (SMAA, Lahdelma и Salminen; интервалы
устойчивости весов для взвешенной суммы, 2025), и почти наверняка его не будет
ни у одной другой команды. Вместе с 4.1 даёт связную историю: «модель без S2
предпочитает C-режимы, с S2 — наш портфель, и вот в каких пределах весов это
верно». П2, П4, Т4.

**Как у нас.** Перенести расчёт из `tools/case02_robustness.py` в
`backend/model.py` (`robustness(records, weights, config, draws, seed)`),
результат в `dashboard.json` → `robustness: {draws, seed, wins: {id: share},
selected: {median_rank, top3_share}, intervals: {weight: [lo, hi]}}` и в
`results/sensitivity.csv` (он запланирован в A-tool.md, но не сделан).
Интерфейс: таблица под «Комбинации в сравнении» плюс строка вывода; кнопка «?»
объясняет метод. 3 000 розыгрышей на stdlib — около 20 с: считать один раз в
`build.py` и кэшировать, seed фиксировать в `model.json`.

**Время.** A: 1,5 ч. B: абзац вывода в раздел 3.

#### 4.10. Режим D «межрегиональный консорциум» — только при готовой причинной истории

**Что.** D = режим B, в котором якорный платёж восстановлен до 100 % за счёт
совместной закупки двух-трёх регионов (k_anchor 1,0), эксплуатация дешевле на
5 % за счёт общей платформы (k_opex 0,95), ценность 0,90, public core = true при
бесплатном базовом слое. Для FIRE-A · AGRI-D · TRANS-D · ENV-A: c0 1 140,
ценность 1 325, cash/OPEX 1,26, четыре public-core лота, STRESS проходит.

**Зачем.** Показывает, что модель доступа можно проектировать, а не только
выбирать; закрывает вопрос 5 из `questions.md`. Но README предупреждает: D без
причинной логики читается как подгонка.

**Как у нас.** Отдельный `config/custom_mode.json` (коэффициенты,
`public_core`, `rationale`, источник), подмешивается в `load_case` с пометкой
«допущение команды»; интерфейс подхватит букву автоматически. Ограничитель в
коде: каждый коэффициент D в пределах [min, max] значений A/B/C («интерполяция,
не экстраполяция»), иначе сборка падает с понятной ошибкой. Экспортировать
`custom_mode.json` рядом с `results/`: это закрывает пробел шаблона организаторов
(§8.8, параметры D не экспортируются).

**Время.** A: 2 ч; D: описание совместной закупки (ст. 25 44-ФЗ, совместные

#### 4.11. Цепочка ценности и KPI с источником в карточках сервисов

**Что.** В `config/lots_ui.csv` добавить столбцы «Действие пользователя»,
«Измеримый эффект», «Источник данных KPI», «Цель на год пилота»; карточка
показывает цепочку «потребность → пользователь → сервис → действие → эффект →
KPI → источник» одним блоком.

**Зачем.** П1 и П9 требуют именно эту цепочку и источник данных для KPI; в
инструменте она станет проверяемым артефактом, а не только текстом.
Методическая опора: цепочка ценности ДЗЗ (Virapongse et al., 2020) и
четырёхшаговая схема VALUABLES (данные → решение → результат → ценность), где
ценность возникает только через изменённое решение пользователя.

**Время.** A: 45 мин; E: содержание для четырёх лотов.

#### 4.12. Тиражирование как таблица «ядро / адаптация / передача»

месте, следующие регионы-архетипы), блок на странице «Портфель».

**Зачем.** П8. Реальный аналог тиражируемого ядра — «Цифровая Земля»

данных с 2025 года — платная закупка через федеральный фонд ДЗЗ (5 млрд руб. на

обязанность покупать данные действует с 01.01.2025; D уточняет дату перед

## 5. Чего не делать

- Хостинг, облако, внешние API, ИИ-объяснения в интерфейсе: баллов не дают
  (README §10.2), времени стоят.
- Не менять веса, чтобы выбранный портфель стал первым: это заметно и прямо
  названо в B-model.md. Вместо этого — явный S2.
- Не называть срок возврата «окупаемостью проекта», не вводить NPV/IRR без
  формул и ставки; kcash — только «покрытие OPEX поступлениями».
- Не снижать c0 лотов в стрессе; не трогать файлы организаторов (хэш-тест это
  фиксирует).
- Не добавлять экраны: макет утверждён, новые блоки — внутри четырёх
  существующих страниц.
- Режим D — только вместе с договорной историей и экспортом его параметров.
