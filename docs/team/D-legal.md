## Что ты делаешь

### 1. Содержание режимов A/B/C (и D, если появится)

Для каждого режима ответить на девять вопросов из README 10.1: кто получает
базовый сервис; кто расширенный; нужна ли идентификация; территориальные
границы; что бесплатно, что платно; права на повторное использование данных;
гарантированный уровень качества; когда доступ ограничивается; как защищена
общественная функция при `public_core`. Связать с коэффициентами: A —
k_commercial 0.25 означает почти бесплатный доступ для рынка, поэтому cash
низкий, а vpub полный; C — наоборот.

### 2. Договорная схема по каждому лоту (П5)

| Лот | Кто закупает | Инструмент закупки | Кто предоставляет | Кто принимает результат | Кто использует | Основные риски у кого |
|---|---|---|---|---|---|---|

Инструменты на выбор, по одному основному на лот с обоснованием:
- госконтракт на услугу или данные (44-ФЗ; для госкорпораций и ГУП 223-ФЗ);
- закупка данных ДЗЗ у частных операторов через федеральный фонд (89-ФЗ от
  22.04.2024, действует с 2026 г.) — для лотов EO;
- соглашение о ГЧП / МЧП (224-ФЗ) — когда частный партнёр несёт c0;
- концессия (115-ФЗ) — если создаётся объект инфраструктуры;
- межрегиональное соглашение о совместной закупке — для тиражирования;
- для SSA — федеральный заказчик, госконтракт.

Плюс RACI по этапам: создание, приёмка, эксплуатация, развитие.

### 3. Реестр рисков (П7)

Привязан к портфелю, не типовой список. Столбцы: риск, событие, причина,
последствие для портфеля, владелец, мера снижения, остаточный риск,
ограничение меры. Минимум по одному на: технологию/готовность (readiness
< 4), спрос (commercial cash не пришёл), регуляторику (доступ к данным ДЗЗ),
запуск/поставщика (единственный оператор), бюджет (переход в STRESS —
ссылка на раздел C), межрегиональную координацию.

### 4. Конкуренция и `supplier_switch_rule`

Как сохраняется конкуренция: квалификация не менее двух поставщиков,
открытые форматы данных и API, права заказчика на данные и модели, срок
контракта и опцион продления, доля одного поставщика в портфеле не выше X %.
Правило смены поставщика: условия (SLA нарушен N раз, цена выше рынка),
процедура, переходный период, кто несёт затраты перехода.

### 5. Чистая проверка в 19:30 (для Т5)

На своей машине: `git clone`, команды из README и ничего больше. Получить
цифры записки. Изменить один лот через интерфейс, увидеть FAIL с порогом и
фактом. Переключить STRESS. Записать, что не сработало, отдать A.
