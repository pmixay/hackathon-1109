# Повторная проверка проекта участника №4

## Область проверки

Сначала был проверен переданный архив `kosmo-calc-engine.zip` (SHA-256: `a7bf128ff7aa0f96d0413d9c7f2906e584e50e7e8cdf61c9cf6488fad3fd3fd0`): в нём независимо прошли 326 тестов, а расчёт рабочего портфеля совпал с каноническим ядром. Затем проверена актуальная ветка [`calc-engine`](https://github.com/pmixay/hackathon-1109/tree/calc-engine), commit [`9699070`](https://github.com/pmixay/hackathon-1109/commit/969907065fa1454708e0d7ea66c74b25e2445964).

## Итог

Ветка №4 приведена к решению экономиста. `config/portfolio.json` и `config/alternatives.json` содержат `FIRE-A + ENV-A + AGRI-B + TRANS-B`; `results/base.json` и `results/stress.json` показывают `c0 = 1140`, `OPEX = 313`, `cash = 370,5`, `K_cash = 1,1837`, `vpub = 1289`. Все проверки BASE/STRESS пройдены; запас по стресс-лимиту `c0` равен 40 млн руб.

`config/assumptions.json` теперь фиксирует частоту, свежесть, задержку, восстановление, резерв, основания и владельца допущений для FIRE/ENV/AGRI/TRANS, а также правила пропусков, истории, API, журнала доступа и контрольной выборки. «Арктика-М» описана как высокоэллиптическая система: 15–30 минут ограничены подтверждённой зоной покрытия, что снимает прежнее расхождение с источником.

## Сверка ответов №4

| Ответ | Результат |
|---|---|
| EO для FIRE/ENV; EO + PNT/InSAR для AGRI/TRANS | Совпадает с `lots.csv`; зафиксировано в `assumptions.json` |
| Два поставщика на критическую группу | Есть как договорное правило; конкретные права и покрытие требуют договора |
| Частоты 15–30 минут, неделя, 5–10 и 6–12 суток | Есть как проектные SLA с условиями покрытия и качества |
| Облачность и пропуски | Есть `stale`, `source_updated_at`, пониженный `confidence`; событие не выдумывается |
| Резерв, CSV/GeoJSON, история, `processing_version` | Описаны в `assumptions.json` как требования эксплуатации |
| REST и журнал доступа | Описаны как целевая архитектура; в `src/kosmo` не реализованы |
| Эталонный набор для смены поставщика | Описан как договорное требование; тесты движка его не заменяют |

## Открытые пункты

- README ветки заявляет 333 теста, но для аудита нужен фактический лог запуска из commit `9699070` или CI. Независимо подтверждены только 326 тестов старого архива.
- Плательщики, юридический заказчик и коммерческий спрос остаются вопросами к участникам №1 и №3.
- Эксплуатационные API, журнал событий и резервирование не следует показывать как готовый код: в репозитории они обозначены целевой архитектурой.

## Решение по приёмке

- Расчётное ядро, конфигурация и результаты: **принять**.
- SLA и эксплуатационная архитектура: **принять как проектные допущения**, с указанными ограничениями.
- Новые изменения в работе участника №2 по составу портфеля не нужны; нужно только заменить старые инструкции на ссылку на `calc-engine` и сохранить границы утверждений.
